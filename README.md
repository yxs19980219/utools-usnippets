# Pattern Vault（模式库）

> 面向开发者的 uTools 模式库：沉淀**经过验证、经常使用**的代码模式与知识笔记，让每一次解法都不被浪费。

## 为什么做「模式库」

开发者的日常里充满"重复发现"：

一个解法，今天花了 30 分钟搜索、阅读、验证才搞定；两周后又遇到几乎一样的问题，结果还得从头搜一遍、再验证一遍。这些解法其实都是**模式**——经过验证、稳定可靠、值得反复使用的知识资产，却被我们一次次重新发现、又一次次随手丢掉。

「模式库」就是为这些模式准备的私人仓库：

```
遇到问题 → 找到解法 → 验证通过 → 存进模式库
下次再遇到 → 搜到即用，不再重新趟坑
```

记录的不是"笔记簿"，而是你亲手验证过的、可以直接信任的**模式**。用的次数越多，它替你省下的时间就越多。

## 产品设计哲学

### 1. 只沉淀"验证过的模式"

模式库的价值在于**可信**。这里存的不是随手粘贴的参考，而是你亲自验证过、确认可复用的解法。存进来 = 通过你的验收，下次可以放心直接使用，不必再怀疑。

### 2. 片段与笔记，各司其职

技术知识天然有两种形态：

- **片段**：拿来就能用的执行单元（一段代码、一个命令、一段配置）——**复制用**
- **笔记**：读一遍就懂的知识单元（设计思路、踩坑记录、架构说明）——**阅读用**

模式库不需要你在创建时纠结"这算片段还是笔记"，通过内容自动识别：全是 Markdown 就是笔记，有代码就是片段。只管记录，类型是自动的事。

### 3. 记录的成本要趋近于零

记录之所以坚持不下来，是因为过程太繁琐。模式库把摩擦降到最低：

- **打开即编辑**，没有"新建 → 填表单 → 保存"的流程
- **自动保存**，永远不用担心忘记保存、丢失内容
- **一键复制**，把沉淀的成果拿出来用时只需一下

记录不打断心流，习惯才养得成。

### 4. 即取即用，快过记忆

模式库的价值在"用得上的那一刻"。独立的搜索视图让取用快过翻笔记：

- 片段级全文搜索，输入即过滤
- 选中 + `Enter` = 直接粘贴到你正在写代码的光标处
- `Ctrl+1~9` = 一条快捷键复制对应片段，立即回到工作现场

**全程不离开你的工作流**——这才是"模式库"该有的体验。

### 5. 随账号走的个人资产

模式库是你的长期资产。数据随 uTools 账号跨设备同步，换台电脑、重装系统，你的模式库依然完整。今天记录的一点，几年后仍是可用的积累。

### 6. 慢慢积累，越用越值钱

模式库是**复利资产**：每记录一个模式，它就替你省一次搜索；记录得越多，检索命中率越高、节省的时间越多。坚持一年后，这就是你最宝贵的个人技术资产之一。

## 功能模块

### 1. 三栏主界面

```
┌──────────┬──────────────┬──────────────────────┐
│ 侧边栏    │  中栏列表     │  编辑区（打开即编辑）   │
│ 库/文件夹 │  记录列表     │  标题栏 + 备注 + 编辑器 │
│ /标签     │  (160px)     │  + 状态栏             │
│ (144px)  │              │                      │
└──────────┴──────────────┴──────────────────────┘
```

- **侧边栏**：库（所有 / 收件箱 / 收藏 / 回收站）、文件夹（右键重命名 / 删除 / 默认片段语言，支持拖入记录）、标签云（右键删除标签）
- **中栏列表**：标题 + 场景摘要，最近修改排序，右键菜单（复制 / 收藏 / 移动分类 / 导出图片 / 移入回收站）
- **编辑区**：标题、备注（场景）、多片段 tab（重命名 / 拖拽排序）、语言切换、标签编辑

### 2. 记录 / 片段

- 一条记录 = 标题 + 场景备注 + 多个片段（可多语言）+ 标签 + 收藏状态
- 多片段 tab 均分宽度，拖拽排序，双击/右键重命名，右键删除
- 自动保存：内容变更 → 防抖 1s → 串行化写库，关闭窗口前 flush

### 3. 文件夹与默认片段语言

- 文件夹可设置**默认片段语言**（排除 markdown，markdown 是笔记专用）
- 在文件夹视图下新建片段 → 自动归入该文件夹并使用其默认语言

### 4. 回收站

- 删除为软删除：记录移入回收站，可一键恢复
- 删除文件夹 → 其下记录全部移入回收站（带数量确认提醒）
- 回收站内可彻底删除（物理删除 + 附件孤儿清理）

### 5. 标签

- 标签云计数排序，点击筛选
- 右键删除标签：从所有记录移除该标签（不影响记录本身）

### 6. 片段搜索视图（独立 feature）

- 片段级全文检索（内容 / 标题 / 场景 / 标签）
- 键盘导航：`↑↓` 移动 / `Enter` 粘贴到原光标处 / `Ctrl+1~9` 复制对应编号并退出
- 每行展示：语言徽标 · 标题 · 归属文件夹（收件箱为黄色图标）· 备注 · 标签

### 7. 图片附件

- markdown 编辑中粘贴图片 → 附件落库（≤10M）→ 光标处插入 `![](att://<id>)`
- 支持导出记录内全部图片（右键菜单）

### 8. 导入 / 导出

- JSON 导出（记录 + 分类 + 附件），导入为合并语义，导入前自动备份到 userData

## 目录结构

```
.
├── public/                    # uTools 接入目录（开发模式加载此目录）
│   ├── plugin.json            # 插件清单（feature 定义、窗口尺寸）
│   ├── logo.png
│   └── preload/
│       ├── services.js        # preload 服务（db / attachment / file，CommonJS）
│       └── package.json
├── src/
│   ├── App.tsx                # 入口：feature 路由（主界面 / 搜索视图）+ 全局加载
│   ├── main.tsx
│   ├── types.ts               # 领域类型（记录 / 片段 / 分类）
│   ├── components/
│   │   ├── Sidebar.tsx        # 左栏：库 / 文件夹 / 标签导航
│   │   ├── ListPane.tsx       # 中栏：记录列表
│   │   ├── EditorPane.tsx     # 右栏：编辑区
│   │   ├── SearchView.tsx     # 片段搜索视图（独立 feature）
│   │   ├── SettingsDialog.tsx # 设置：深色 / 默认语言 / 导入导出
│   │   ├── editor/            # 编辑器组件（CodeBlock / MarkdownEditor /
│   │   │                      #   FragmentTabs / StatusBar / TagEditor）
│   │   └── ui/                # shadcn 基础组件（button / dialog / select ...）
│   ├── stores/                # Zustand stores（records / categories / settings / ui）
│   ├── lib/                   # 领域逻辑（db / search / languages / clipboard ...）
│   └── styles/globals.css     # 设计 Token + 全局样式（Tailwind 4）
├── dist/                      # 构建产物（发布模式加载此目录）
├── vite.config.ts             # base './' + Lightning CSS 降级 + dev 5175
└── package.json
```

### 数据流分层

```
组件（React）  →  stores（Zustand）  →  lib/db.ts（唯一数据入口）  →  preload services  →  utools.db
```

渲染进程不直接调用 `window.services`，一律经 `lib/db.ts` 集中访问，保证数据入口统一。

## 开发

### 环境要求

- Node.js ≥ 18
- uTools（开发时用插件开发工具加载 `public/` 目录）

### 常用命令

```bash
npm install        # 安装依赖
npm run dev        # 启动 Vite dev server（固定端口 5175，HMR）
npm run build      # 类型检查 + 构建到 dist/（tsc -b && vite build）
npm run preview    # 预览构建产物
```

### 开发 / 发布双模式

| 模式 | 加载目录 | 说明 |
|------|----------|------|
| 开发（HMR） | `public/` | `plugin.json` 保留 `development.main` 指向 dev server |
| 发布 | `dist/` | 构建产物；`stripDevelopmentField` 插件自动移除 `development` 字段 |

### 发布与版本

- 版本事实来源为 **git tag**（`vX.Y.Z`），`public/plugin.json` 不含 version
- 每次推送用户可见变更必须同步打 tag 并推送：
  ```bash
  git tag vX.Y.Z && git push origin vX.Y.Z
  ```
- `package.json` 的 `version` 与最近 tag 保持一致
- 语义化：新增功能 → minor，纯修复 → patch

### uTools 环境注意事项

- preload 必须 CommonJS，源码可读不压缩
- `utools.db` 只存用户主动创建的数据；偏好存 `dbStorage`
- 路径处理用 `path.join()`，不硬编码分隔符
- 现代 CSS 需 Lightning CSS 降级到 Chrome 88（已配置，勿移除）
